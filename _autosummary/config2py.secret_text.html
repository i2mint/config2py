config2py.secret_text#

Value-level detection of credentials in free text.

config2py.util.looks_like_secret() judges a key name (OPENAI_API_KEY); has_secret() judges a value: it is for text about to be written somewhere others can read it (a report, an issue body, a log line), where the credential is in the text rather than in its label.

Module Attributes

SECRET_TEXT_PATTERNS

Shapes of a credential in free text (some prefix alternatives here are looser than the matching SECRET_RULES entry, kept so no earlier match is lost): a header or cookie line, a secret-named key with a value (any value for a password, secret or key; an opaque one holding a digit for a token, session or auth key), credentials in a URL, a JWT, a known key prefix, or a long opaque string with at least four digits.

PRIVATE_KEY_PATTERN

PEM's ``-----BEGIN .

TOKEN_SHAPES

the GitHub (ghp_ and its siblings, github_pat_), sk- API key, AWS access key, Hugging Face (hf_) and Slack (xoxb- and its siblings) shapes.

TOKEN_RULES

The rule id of each of TOKEN_SHAPES, in order.

TOKEN_LITERALS

The literals every match of each of TOKEN_SHAPES contains, in order.

SECRET_RULES

the token shapes and private-key header, then distinctive-prefix rules adapted from gitleaks (the gitleaks id precedes each).

Shapes of a credential in free text (some prefix alternatives here are looser than the matching SECRET_RULES entry, kept so no earlier match is lost): a header or cookie line, a secret-named key with a value (any value for a password, secret or key; an opaque one holding a digit for a token, session or auth key), credentials in a URL, a JWT, a known key prefix, or a long opaque string with at least four digits. Errs on the side of flagging: a false positive keeps a harmless fact out of public text, a false negative publishes a secret.

class config2py.secret_text.SecretRule(rule, pattern, literals=(), word_start=True, wrappable=True, ignore_case=False)[source]#

Bases: object

A secret’s shape: rule names it, pattern is its expression.

Data only; the matching engine is the user’s (liaise scans message views with it, has_secret() a plain string). literals: strings one of which every match contains (in case-folded text, with ignore_case), a cheap pre-filter; empty: always scan. word_start: a match must start a word. wrappable: a hint for engines that also look for the rule in text with line breaks and markup removed (a token split by them): such a pattern must not fail after an unbounded repetition. has_secret() scans the text as given and ignores it.
